# Calculator review — 17 October 2026

PR #62 is reconciled with public main `990ff835`, including the shared visual standard, published fire reference, Guide and Contact releases. No sibling draft PR is merged to obtain calculator changes. The calculator remains at `/calculator/` with its own desktop/mobile menu destination. `/advice/quantities/` remains a written guide; calculation links at the old address forward to the calculator.

## Corrections

- Opening dimensions are checked against physical wall widths, including combined openings. Invalid input cannot yield a negative material area.
- Length orders allow the spare from the tallest entered wall. Roll-capacity labels are no longer truncated at 1,000 drops. Invalid or excessively large plans return a clear check/measurement request instead of allocating an unbounded cutting plan.
- Repeat and dimension unit changes preserve the measurement. Shared links retain that precision, carry the product link and reject malformed enum values safely. Selecting a new preset clears the previous exact-dimension cache.
- A stale result has a real status notice and inactive send/share controls. Field errors cover trims, reveal depths and returns. A mural requires an explicitly entered maker margin, including an explicit zero where appropriate.
- Per-roll paste coverage applies only to compatible, source-checked standard roll formats. Unconfirmed rules, unknown paste steps and product-specific backing exclusions require a check rather than a definite purchase quantity. The four paste steps are labelled as house practice.

## Visual decision

Use the shared `Base`, `Action` and `Icon` system. Retain the warm palette and editorial fonts. The empty order panel carries an original wall-measurement elevation, labelled illustrative and not to scale. Result graphics show the engine's actual cut positions and lengths; a separate spare stays uncut. No second quantity algorithm, stock room decoration or invented project evidence is used. Preparation/material pages remain text-led because tables, conditions and source links communicate their purpose better than unrelated photographs.

Before captures are kept locally in `.review-screens/before/`. Reviewed first-load, order and cutting-plan captures at 390px and 1440px are in `docs/design/calculator-review/`; the complete eight-width report and print PDF are in `.review-screens/calculator/`. Reproduce with `CHROME_PATH=… npm run capture:calculator` after building both this branch and a sibling `mw-main-base` worktree.

Worked examples, regression tests and browser checks are synthetic verification and do not establish real-job calibration. Keep PR #62 in draft until that condition is resolved by the owner.
